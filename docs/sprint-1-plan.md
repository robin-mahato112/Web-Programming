# Sprint 1 Plan

## Objective

Prepare a demonstrable React foundation, page prototypes, wireframes, and planning material for the Start-Up SCRUM. This sprint does not include a production backend, authentication, checkout, or database integration.

## Sprint backlog

| Work item | Owner | Sprint 1 outcome | Done when |
| --- | --- | --- | --- |
| Catalogue, search, details, cart | Robin | Responsive prototypes using isolated mock products | Routes render, search has empty state, cart is clearly a prototype |
| Registration, login, profile | Member 2 | Accessible forms and client-side validation examples | Labels/errors work with keyboard and no account creation is claimed |
| Admin, user/product management, employee access | Member 3 | Read-only management prototypes | Role boundaries and future database dependency are documented |
| Shared foundation | Whole team | Vite, routing, layout, theme, components | Lint/build pass and team reviews changes |

## Suggested sequence

1. Agree on requirements, roles, code of conduct, and questions for the lecturer.
2. Review wireframes and shared component names.
3. Build the shared layout and reusable controls.
4. Develop each member's prototype pages in small branches.
5. Review accessibility at keyboard and mobile widths.
6. Run lint and production build; prepare the Start-Up SCRUM demonstration.

## Definition of done for Sprint 1

- All documented prototype routes load and are navigable.
- Layout adapts to mobile and desktop widths.
- Forms have labels, example validation, and visible focus indicators.
- Mock data is clearly separate from future database integration.
- Documentation accurately distinguishes prototypes from completed systems.
- The team can explain ownership, limitations, and next steps.
