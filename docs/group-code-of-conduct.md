# Group Code of Conduct

## How we work

- Be respectful, inclusive, punctual, and prepared.
- Discuss ideas and code without attacking the person who proposed them.
- Give early notice if a deadline or meeting cannot be met.
- Keep work visible through issues, branches, and small reviewable commits.
- Ask before changing code owned by another member when the intent is unclear.
- Review pull requests constructively and acknowledge feedback.
- Never claim another member's work or create contribution evidence on their behalf.
- Protect credentials and personal data; never commit secrets or real customer records.

## Decisions and disagreements

The team should first seek consensus using assignment evidence and a small technical example. If consensus is not possible, record the alternatives and use a majority decision. Questions that could affect marking or scope should be taken to the lecturer/tutor rather than guessed.

## Accountability

Each member records their actual work using honest commits and the contribution template. At the weekly check-in, members state what is complete, what is next, and any blocker. Repeated unresolved participation issues should be documented factually and raised through the course process.
